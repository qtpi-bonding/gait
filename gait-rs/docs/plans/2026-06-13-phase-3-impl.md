# Phase 3 — Workflow under the I/O boundary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the workflow runner under the Phase-1/2 I/O boundary — workflow events (`workflow_start`, `node_*`, `hook_run`, `workflow_gate`, `workflow_complete/error`) stop echoing NDJSON to **stdout** via `wire::emit` and instead go through a `Recorder` (commit + publish) consumed by a `StdioSink` (Trace→stderr, Error→stderr), and the prompt node's sub-turn publishes to the workflow's live channel instead of a dropped receiver.

**Architecture:** Create one `StreamItem` channel + `Recorder` in `run_workflow`; spawn a consumer task that `drive`s a `StdioSink` concurrently with the node loop. Convert the 11 in-loop `wire::emit` sites to `rec.record(...)` (threading `&Recorder` through `execute_node`/`exec_gate_node`/`propagate_branch_skips` in place of `tx_path: &Path`), extend Phase-1 `classify` to route `Raw{workflow_error|node_error}`→Error, migrate the standalone `gait.rs` abort to `wire::append`, delete `wire::emit`, then (3b) thread the workflow sender into the sub-turn via `NodeContext`.

**Tech Stack:** Rust, tokio (`unbounded_channel`, `tokio::spawn`), prost + pbjson, `anyhow`. Tests via `cargo test`.

**Spec:** [`../specs/2026-06-13-phase-3-workflow-boundary.md`](../specs/2026-06-13-phase-3-workflow-boundary.md). Parent plan: [`2026-06-13-turn-io-architecture.md`](./2026-06-13-turn-io-architecture.md).

**Testing note (from CLAUDE.md):** always redirect to a file then grep:
```bash
cargo test 2>&1 > /tmp/t.txt; echo "exit: $?"; grep "test result\|^error\|FAILED" /tmp/t.txt
```

**Risk:** This is the riskiest phase. Split 3a (channel + raw classify + emit→record + delete `wire::emit`) before 3b (sub-turn re-plumbing) so each is independently reviewable and green. The 3a `run_workflow` restructure (Task 2) is load-bearing: the consumer must be **awaited on every exit path** (success and `bail!`) or events race process exit.

## Task 2: `run_workflow` records through a `Recorder` + live consumer (load-bearing)

**Files:** `src/workflow/runner.rs` (`run_workflow` `:28`, `execute_node` `:237`, `propagate_branch_skips` `:281`), `src/workflow/exec_gate.rs` (`exec_gate_node` `:6`). No new test here — the channel/stdout behavior is asserted in Task 3's migration test and the full suite is the gate (this is a mechanical rewrite that must stay green).

**Background:** `tx_path` (`runner.rs:34`) is still needed for `read_events` (`:36`), so keep it. Build `rec` alongside (same path). The 11 emit sites are: direct in `run_workflow` body — `:48,63,88,102,109,139,162,174,192,220`; and `:303` inside `propagate_branch_skips`. Plus `exec_gate.rs:15`.

- [ ] **Step 1:** At the top of `run_workflow`, after `tx_path`/state reconstruction (`runner.rs:34-37`), create the channel, `Recorder`, and spawned consumer:
```rust
    let (tx, rx) = tokio::sync::mpsc::unbounded_channel::<crate::proto::gait::log::v1::StreamItem>();
    let rec = crate::proto::Recorder::for_session(&gait_dir, &session_id, tx);
    // Consume the channel concurrently with the node loop: Trace→stderr, Error→stderr.
    let consumer = tokio::spawn(async move {
        let mut sink = crate::cli::output::StdioSink::stdio(false);
        crate::port::output::drive(rx, &mut sink).await;
        sink.failed
    });
```
- [ ] **Step 2:** Wrap the **entire** remaining node-loop body (everything from the `workflow_start` emit down to the final `Ok(())`) in an inner async block bound to a result, so cleanup runs on every path. **Critical:** there is a `std::process::exit(0)` mid-loop on the gate-pause branch (`runner.rs:154`) — a hard process exit terminates immediately, skipping `drop(rec)`/`consumer.await`, so buffered events (incl. `workflow_gate`) never flush. The gate pause is a **normal** path (every gate), not an error edge. So the inner block must **return a value** for "gate paused" instead of exiting in place, and the outer scope exits 0 *after* draining. Define an outcome enum and restructure:
```rust
    enum Outcome { Completed, GatePaused }

    let run_result: anyhow::Result<Outcome> = async {
        // ... the existing node-loop body, with every `wire::emit(&tx_path, X)?`
        //     rewritten to `rec.record(X)?;` (record returns Result<Event>) ...
        //
        // At the gate-pause branch (was `std::process::exit(0)` at runner.rs:154):
        //     keep the state.set_status / update_progress / commit_session /
        //     eprintln!("[gait workflow] paused at gate …") lines, then:
        //         return Ok(Outcome::GatePaused);   // <-- replaces std::process::exit(0)
        //
        eprintln!("[gait workflow] complete: {}", wf.name);
        Ok(Outcome::Completed)
    }.await;

    drop(rec);                                      // close the channel → consumer's drive() returns
    let _failed = consumer.await.unwrap_or(false);  // flush stderr before returning/exiting
    match run_result? {                             // `?` propagates a bail! AFTER draining
        Outcome::GatePaused => std::process::exit(0), // semantics preserved: hard exit 0, now flushed
        Outcome::Completed => Ok(()),
    }
```
Notes: (a) `_failed` is intentionally unused — a workflow error already propagates as `Err` via `bail!`, which `bin/gait` maps to `exit(1)`; the consumer never calls `diagnostic`, so `failed` is always `false` here. Do **not** wire `_failed` to the exit code: a `node_error` with `on_error: continue` deliberately does **not** fail the run, and routing it through `failed` would wrongly fail continue-workflows. (b) `?` inside the inner `async {}` returns from the **block** (into `run_result`), not the function, so `bail!`/`?` on `node_error` are caught and still hit the drain. (c) confirm no other `std::process::exit` / `return` hides inside the loop body that would bypass the block.
- [ ] **Step 3:** Rewrite the 10 in-body `wire::emit(&tx_path, wire::raw(...))?` calls (`:48,63,88,102,109,139,162,174,192,220`) to `rec.record(wire::raw(...))?;`. Mechanical — the `wire::raw(...)` argument is unchanged; only the call wrapper changes. Example (`:48`):

- [ ] **Step 1:** Add the sender to `NodeContext` (`exec_shell.rs:5`):

```rust
pub struct NodeContext<'a> {
    pub workflow_id: &'a str,
    pub session_id: &'a str,
    pub gait_dir: &'a Path,
    pub codebase: &'a Path,
    pub vars: VarContext,
```

- [ ] **Step 2:** Add the `Recorder::sender()` accessor (`src/proto/emitter.rs`), so the `NodeContext` can **borrow** `rec`'s sender rather than hold a second long-lived clone:
```rust

    /// the same channel). Cloning this lives only as long as the child; the owning
    /// Recorder remains the single long-lived sender, so dropping it closes the channel.
    pub fn sender(&self) -> &tokio::sync::mpsc::UnboundedSender<crate::proto::gait::log::v1::StreamItem> {
```
