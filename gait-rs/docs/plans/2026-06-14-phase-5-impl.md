> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make "drive gait by implementing the I/O ports" a real, public, ergonomic Rust embedding API: relocate `run_loop` out of `cli::` into a neutral `embed` module, curate a one-`use` `gait_ai::embed` facade, add a `resolve_caps` helper, and prove it with an external-style worked example. Zero turn/log/retrace changes.

**Architecture:** Phases 1–4 already produced the embeddable core (`run_loop` + `TurnSource`/`TurnSink`/`TurnDriver`). Phase 5 is **packaging**: move the loop to `src/embed.rs`, re-export the port surface there, dedupe caps-building into `embed::resolve_caps`, and add `tests/integration_embed.rs`. FFI and network transport are explicitly deferred (each is just a new adapter pair over `embed::run_loop`).

**Tech Stack:** Rust, `#[async_trait(?Send)]`, tokio, `anyhow`. Tests via `cargo test`.

**Spec:** [`../specs/2026-06-13-phase-5-embedding-api.md`](../specs/2026-06-13-phase-5-embedding-api.md). Parent: [`2026-06-13-turn-io-architecture.md`](./2026-06-13-turn-io-architecture.md).

## Task 2: `embed::resolve_caps` helper + dedupe, and `JsonSink` (FFI-shaped pbjson output)

**Files:** `src/embed.rs` (add `resolve_caps` + `JsonSink`), `src/repl_loop.rs` (`ReplDriver::caps` calls it).

**Why `JsonSink`:** the intended consumers (Serverpod/Flutter) call gait FFI-style and read **pbjson** (the protobuf→JSON mapping gait already uses everywhere) — they can't implement a Rust `TurnSink`, but they can pass a callback. `JsonSink` is the bridge: it serializes each frame to pbjson (identical to `StdioSink`) and hands the string to a closure (which a future C-ABI shim maps to an `extern "C"` fn pointer). No Rust types cross the boundary; the consumer parses the JSON with a model generated from the same `.proto`.

- [ ] **Step 1:** Add `JsonSink` to `src/embed.rs`:
```rust
/// A frame handed to a `JsonSink` callback. Strings are pbjson (canonical
/// protobuf-JSON) the consumer parses with classes generated from the .proto.
pub enum JsonFrame<'a> {
    Item(&'a str),              // pbjson StreamItem (a Trace/Error event or delta)
    Result(&'a str),            // pbjson RunResult ({message,result,changes})
    Diagnostic(Diag, &'a str),
}

/// A `TurnSink` that serializes each frame to pbjson (byte-for-byte StdioSink's
/// output) and calls `f`. The FFI-ready sink: drive a turn, get pbjson out.
/// `failed` mirrors `StdioSink` (set on an error diagnostic) for exit-code parity.
pub struct JsonSink<F: FnMut(JsonFrame<'_>)> { pub f: F, pub failed: bool }
impl<F: FnMut(JsonFrame<'_>)> JsonSink<F> {
    pub fn new(f: F) -> Self { Self { f, failed: false } }
}
impl<F: FnMut(JsonFrame<'_>)> TurnSink for JsonSink<F> {
    fn item(&mut self, item: &StreamItem) {
        if let Ok(j) = serde_json::to_string(item) { (self.f)(JsonFrame::Item(&j)); }
    }
    fn result(&mut self, r: &TurnResult) {
        if let Ok(j) = serde_json::to_string(&run_result_proto(r)) { (self.f)(JsonFrame::Result(&j)); }
    }
    fn session_id(&mut self, _id: &str) {}
    fn diagnostic(&mut self, level: Diag, msg: &str) {
        if level == Diag::Error { self.failed = true; }
        (self.f)(JsonFrame::Diagnostic(level, msg));
    }
}
```
(`StreamItem`/`RunResult` are pbjson-`Serialize` — `StdioSink` already does `serde_json::to_string(item)`. `run_result_proto` is re-exported via the facade. Raw wire bytes remain available via `prost::Message::encode_to_vec` if a consumer ever wants binary; not the default.)

- [ ] **Step 2:** Add `resolve_caps` to `src/embed.rs`. It takes a **resolved** `agent_path: Option<&Path>` (what both drivers already hold — no name re-resolution), matching `Profile::from_config_and_agent`'s arg exactly:
```rust
use std::path::Path;

/// Resolve a live profile (provider + tools + MCP) for one session from config +
/// optional agent file + optional model override — the same default resolution the
/// CLI and REPL do. Embedders use this instead of touching `Profile` internals.
pub async fn resolve_caps(
    gait_dir: &Path,
    codebase: &Path,
    session_id: &str,
    agent_path: Option<&Path>,
    model_override: Option<String>,
    repos: &Repos,
) -> anyhow::Result<ResolvedProfile> {
    let config = crate::config::load_config(gait_dir);
    let profile = crate::profile::Profile::from_config_and_agent(
        &config, gait_dir, Some(codebase), agent_path, model_override);
    let api_key = crate::auth::resolve_api_key(
        profile.model.split_once('/').map(|(p, _)| p).unwrap_or(&profile.model));
    profile.resolve(codebase.to_path_buf(), session_id.to_string(), gait_dir.to_path_buf(), repos.clone(), api_key).await
}
```

    let items: std::rc::Rc<std::cell::RefCell<Vec<String>>> = Default::default();
    let result: std::rc::Rc<std::cell::RefCell<Option<String>>> = Default::default();
    let (it, rs) = (items.clone(), result.clone());
    let mut sink = embed::JsonSink::new(move |frame| match frame {
        embed::JsonFrame::Item(j)   => it.borrow_mut().push(j.to_string()),
