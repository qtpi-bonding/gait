# ToolCtx Refactor + CWD Hardening

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Introduce a `ToolCtx` struct so all tools receive context through a single typed value
instead of loose constructor params, and harden the two `rg` invocations that inherit process CWD.
After this, `gait run` from any directory with `--codebase <path>` is correctly supported with
zero CWD assumptions in tool code.

**Architecture:** Audit confirms tools are already largely CWD-safe — `codebase_path` is threaded
into every tool constructor and used for path resolution; shell sets `.current_dir()` explicitly;
all git ops use libgit2 with explicit paths. The main changes are: (1) introduce `ToolCtx` to
consolidate the per-tool constructor params and make future additions a one-line change, (2) add
`.current_dir()` to the two `rg` subprocess calls in `grep.rs` and `ls.rs`.

**Tech Stack:** Rust, `cargo test`.

---

## Audit findings

| Tool | CWD pattern | Status |
|------|-------------|--------|
| `read.rs` | `codebase_path.join(relative)` | Safe |
| `write.rs` | `codebase_path.join(relative)` | Safe |
| `edit.rs` | `codebase_path.join(relative)` | Safe |
| `glob.rs` | `codebase_path.join(relative)` | Safe |
| `grep.rs` path resolution | `codebase_path.join(relative)` | Safe |
| `grep.rs` `rg_search()` | `Command::new("rg")` — no `.current_dir()`, but arg is absolute | Fragile |
| `ls.rs` path resolution | `codebase_path.join(relative)` | Safe |
| `ls.rs` `collect_files_rg()` | `Command::new("rg")` — no `.current_dir()`, but arg is absolute | Fragile |
| `shell.rs` | `.current_dir(&codebase_path)` explicit | Safe |
| `git/codebase.rs` | `Repository::open(explicit_path)` | Safe |
| `git/checkpoint.rs` | `Repository::open(explicit_path)` | Safe |
| `git/trace.rs` | `Repository::open/init(explicit_path)` | Safe |

The two `rg` invocations are safe today (absolute path is passed as an argument so rg finds it
regardless of CWD), but they don't express the intent. Hardening them makes the safety invariant
visible at the call site.

- [ ] **Step 1: Create `ctx.rs`**

Create `gait-rs/src/tools/ctx.rs`:

```rust
use std::path::PathBuf;

#[derive(Clone, Debug)]
pub struct ToolCtx {
    pub codebase_path: PathBuf,
    pub gait_dir: PathBuf,
    pub session_id: String,
}

impl ToolCtx {
    pub fn new(codebase_path: PathBuf, gait_dir: PathBuf, session_id: String) -> Self {
        Self { codebase_path, gait_dir, session_id }
    }
}
```

- [ ] **Step 2: Add `mod ctx; pub use ctx::ToolCtx;` to `tools/mod.rs`**

- [ ] **Step 3: Update `builtin_tools()` signature**

In `gait-rs/src/tools/mod.rs`, change the signature of `builtin_tools` from:

```rust
pub fn builtin_tools(
    session_id: String,
    codebase_path: PathBuf,
    gait_dir: PathBuf,
    repos: crate::git::Repos,
) -> Vec<Box<dyn Tool>>
```

to:

```rust
pub fn builtin_tools(
    ctx: ToolCtx,
    repos: crate::git::Repos,
) -> Vec<Box<dyn Tool>>
```

Update the body to destructure: `let ToolCtx { codebase_path, gait_dir, session_id } = ctx;` and
pass fields to constructors as before (constructors are updated in later steps; keep existing
constructor calls compiling by passing the fields directly until all constructors are updated).

- [ ] **Step 4: Update each tool to accept `ToolCtx`**

For each tool, replace the separate `codebase_path: PathBuf, gait_dir: PathBuf` constructor params
with a single `ctx: ToolCtx`. Store `ctx` on the struct. Update all `self.codebase_path` and
`self.gait_dir` accesses to `self.ctx.codebase_path` / `self.ctx.gait_dir`.

Tools that currently take only `codebase_path` (read, write, edit, glob, grep, ls) still get the
full `ToolCtx` — they'll just only use `ctx.codebase_path` today, and the struct is ready for
future fields.

For tools that take `session_id` (spawn_agent), use `ctx.session_id` instead.

Pattern for each file:

```rust
pub struct ReadTool {
    ctx: ToolCtx,
}

impl ReadTool {
    pub fn new(ctx: ToolCtx) -> Self {
        Self { ctx }
    }
}
// Inside impl: self.ctx.codebase_path instead of self.codebase_path
```

fn rg_search_does_not_depend_on_process_cwd() {
    // Changing CWD must not affect results because rg receives absolute path.
    // We verify this by checking the spawned command has current_dir set.
    // (Full integration test: invoke rg_search from a CWD that differs from search_path

- [ ] **Step 2: Add `.current_dir()` to `rg_search()` in `grep.rs`**
